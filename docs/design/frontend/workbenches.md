# 工作台页面范围与验收锚点（IGA/PAM · Risk · WLI）

> 设计锚点：[DESIGN:frontend/workbenches]

> 目标态规范：定义 IGA/PAM、Risk、WLI 三个控制台工作台的页面结构、操作面与验收口径。
> 验收条目以 [acceptance-criteria.md](../../acceptance-criteria.md) 的 `AC-IGA-*` / `AC-RISK-*` / `AC-WLI-*` 为准；
> 需求正文见 [requirements/functional.md](../../requirements/functional.md)；接口契约以 [openapi.yaml](../../../openapi/openapi.yaml) 为唯一事实源，
> 复现命令：`python3 -c "import yaml;d=yaml.safe_load(open('openapi/openapi.yaml'));print(*[p for p in d['paths'] if p.startswith('/api/v1/iga')],sep='\n')"`。

---

## 1. 通用页面骨架

三个工作台共享同一页面骨架，差异只在 Tab 组合与操作面：

| 组成 | 约定 |
|------|------|
| 容器 | 资源页卡片（`gl-resource-page` + `gl-panel gl-resource-card`），标题区展示工作台名称与一句话说明 |
| Tab | 每个 Tab 对应一个聚合根（请求/工单、决策、信号、池、信任、账号），Tab 内以 `ResourceListCard` 渲染 |
| 列表 | 服务端分页 + 关键词检索 + 状态筛选；列定义固定 `width`，操作列 `fixed: right` |
| 详情 | 路由级详情页或抽屉；必须展示状态机当前态、审计摘要与关联对象链接 |
| 操作 | 写操作一律走 `PermissionGuard` + 二次确认；成功后失效对应 query key 并提示 |
| 权限 | 读操作绑定 `<domain>:read`，写操作绑定 `<domain>:write`；缺失权限时按钮不渲染而非禁用 |
| 审计 | 每个写操作携带审计事件；事件名与字段以 [registries](../../registries/README.md) 与审计设计为准 |

## 2. IGA/PAM 工作台

路由前缀 `/iga`（PAM 视图复用同一工作台，通过 Tab 区分能力域）。

### 2.1 页面范围

| Tab | 聚合根 | 操作面 |
|-----|--------|--------|
| 访问请求（Access Requests） | 工单（提交 → 多级审批 → 授予 → 回收） | 提交申请、审批/驳回、撤回、查看审批链与时间窗 |
| 认证 Campaign | 访问认证活动 | 新建活动、启动/暂停/结束、查看覆盖范围与完成率 |
| SoD 规则 | 职责分离互斥规则 | 新建/编辑规则、启用/停用、冲突预检预览 |
| 访问生命周期 | 授予/回收事件流 | 只读检索 + 单条事件详情（含触发来源与幂等键） |
| 特权会话（PAM） | 特权凭证与提权会话 | 提权申请、审批后进入会话、实时告警查看、会话录制回放入口 |

### 2.2 验收锚点

| 锚点 | 页面必须可验收的行为 |
|------|----------------------|
| AC-IGA-001 | 申请表单提交后生成工单并展示审批链预览；时间窗（开始 + 时长 + 范围）在详情中可见；到期后生命周期事件流出现回收事件；重复扫描不产生重复事件 |
| AC-IGA-002 | 未审批的提权请求不出现"进入会话"入口；审批通过后会话带特权标记；特权期间操作可在审计页检索到，且告警可实时到达 |

### 2.3 页面约束

- 申请表单不做前端 SoD 结论裁决：提交后由服务端返回冲突结果，页面只呈现"冲突/通过"与冲突对象。
- 审批链展示为有序步骤（审批人角色 + 当前节点 + 已处理时间），不允许前端重排。
- "进入特权会话"入口仅在服务端返回已批准且未过期时渲染；过期态直接展示回收时间，不再轮询。
- 访问生命周期 Tab 只读，不提供"手动补授"入口，避免绕过审批链。

## 3. Risk 工作台

路由前缀 `/risk`。

### 3.1 页面范围

| Tab | 聚合根 | 操作面 |
|-----|--------|--------|
| 风险信号 | 原始信号（设备指纹、IP 信誉、地理速度、撞库） | 只读检索 + 详情；支持按用户/来源/严重级别筛选 |
| 风险决策 | 分级决策与 step-up 记录 | 复核（改判）、误报申诉受理、查看决策依据 |
| 会话治理 | 风险触发的会话处置动作 | 只读检索；跳转到会话详情执行强制下线 |

### 3.2 验收锚点

| 锚点 | 页面必须可验收的行为 |
|------|----------------------|
| AC-RISK-001 | 决策详情展示风险级别与联动动作（step-up / 完整 MFA / 拒绝）；critical 决策可见"已通知用户与管理员"的审计条目；申诉入口对误报可用且处理留痕 |
| AC-RISK-002 | 会话治理记录可定位到具体会话并跳转强制下线；跳转后会话列表在吊销清单内状态即时更新 |
| AC-RISK-003 | 审计完整性校验结果在 Risk 工作台呈现断链位置与校验时间；校验为只读操作 |

### 3.3 页面约束

- 决策复核只能收紧风险处置，不得放宽既有静态策略；表单不提供"关闭全部风险策略"类批量开关。
- critical 决策不允许"一键放行"，复核必须填写理由并留痕。
- 会话治理 Tab 不直接执行下线，强制下线复用会话域的独立权限点，避免越权面扩大。

## 4. WLI 工作台

路由前缀 `/workload`。

### 4.1 页面范围

| Tab | 聚合根 | 操作面 |
|-----|--------|--------|
| 身份池 | Identity Pool | 列表 + 选择（作为后续 Tab 的作用域）、新建 |
| 联邦信任 | OIDC 信任源 | 在选中池内新建/查看；展示 issuer、audience 白名单与 subject 白名单 |
| Service Account | 一等主体 | 在选中池内新建、轮换凭据、禁用/启用、删除（带关联预检） |

### 4.2 验收锚点

| 锚点 | 页面必须可验收的行为 |
|------|----------------------|
| AC-WLI-001 | Service Account 列表可区分于人类用户；删除前展示关联凭据/授权预检结果；创建成功后一次性展示 Client Secret 且不可再次读取 |
| AC-WLI-002 | 联邦信任创建表单强制 issuer/JWKS/audience 白名单字段；subject 白名单支持受控通配预览；凭据时效策略在创建服务账号时可见且默认短期 |

### 4.3 页面约束

- 未选中身份池时，联邦信任与 Service Account 两个 Tab 呈现"先选择身份池"引导态，不渲染空表格。
- Client Secret 只在一处一次性展示，关闭弹窗后列表仅显示"已配置"标记。
- 静态长效凭据创建被拒绝时，页面展示门禁原因与豁免申请入口，而不是通用错误提示。

## 5. 验收口径

三个工作台按同一口径验收，任一 Tab 不达标即视为该工作台未完成：

| 维度 | 判定标准 |
|------|----------|
| 列表 | 首屏加载、分页、检索、排序与筛选均走服务端参数，刷新后条件保持 |
| 详情 | 直接访问详情路由可回显完整对象；刷新后状态与列表一致 |
| 操作 | 写操作有权限守卫、二次确认、成功提示与列表失效；失败保留表单输入 |
| 空态/错误态 | 无数据展示空态；接口失败展示可重试错误态，不出现空白页 |
| 权限 | 只读账号看不到任何写入口；越权请求返回 403 并按统一错误体展示 |
| 响应式 | 桌面与窄视口下操作列不溢出、Tab 可横向滚动切换 |
| 端到端 | 每个工作台至少一条 Playwright 用例覆盖"列表 → 详情 → 关键写操作 → 刷新回显" |

## 6. 列表 / 详情 / 表单的页面边界

三个工作台以及其余控制台页面按同一套边界实现，避免同类页面各写一套：

| 页面类型 | 边界要求 | 实现锚点 |
|---|---|---|
| 列表 | 首屏、分页、检索、排序、筛选全部走服务端参数；刷新后条件保持；空态/错误态/权限态齐全 | `CrudListPage`、`ResourceListCard` |
| 详情 | 直接访问详情路由即可回显完整对象（不依赖列表跳转传入的状态）；刷新后与列表一致 | 详情页 `useQuery` + 路由参数 |
| 表单 | 创建/编辑共用同一套字段与校验；提交锁、未保存保护、成功提示、失败保留输入一致 | `ResourceFormPage`、`GlFormRow`、`GlFormGrid` |
| Tab 工作台 | Tab 选择写入 URL，可刷新与直达；每个 Tab 独立查询键；切换 Tab 不丢已选筛选 | 详情页 Tab 组件 |

宽度与溢出策略以 [interaction.md](interaction.md) 的「内容宽度三档」为唯一事实源：
列表/仪表盘 1600px、表单/详情 1200px、阅读型设置 960px；表格列宽显式声明并允许
容器内横向滚动，固定操作列不得被裁切。

## 7. 页面族与扫描门禁

控制台页面装配 AppShell，主显示区为 `.gl-content__inner`；独立认证页使用
`.gl-auth-background` / `.login-content` / `.gl-panel` / `.gl-standalone-page` 之一
（清单与宽度策略见 interaction.md「独立认证页的页面家族」）。

`web/e2e/route-sweep.spec.ts` 以 `docs/design/frontend/registry.md` 为唯一页面清单，
在 390 / 768 / 1024 / 1440 / 1920 五档视口逐一断言：

1. HTTP 状态非 5xx，且未落入错误边界；
2. 命中上述页面壳层之一（防止新页面使用无名内联容器）；
3. 无横向溢出、三档宽度不越界、表格容器不超出视口；
4. `console.error` 与 `pageerror` 为 0（antd 弃用 API 会以 `console.error` 暴露）。

动态路由缺少稳定夹具时显式 SKIP 并注明原因，不记为通过。

**租户参数与扫描口径**：列表页的 `?organizationId=` 与请求体 `organizationId` 都是
服务端待裁决的「目标租户」，不是可信来源：`TenantResolutionMiddleware` 会把 query/body
中的组织值解析为跨租户目标，非平台管理员使用他租户 UUID 由 ScopeAuthorizer 拒绝，
使用他租户 slug 直接 403；本租户 UUID/slug 不标记为目标（避免普通用户被自身租户参数误拒）。
因此扫描用例可以携带会话租户的 `organizationId`，但不得用夹具伪造他租户值来「通过」。

页面级 10 项 rubric（R1–R10）与提交语义见 [interaction.md](interaction.md)「页面级验收 rubric」。
