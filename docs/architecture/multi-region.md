# multi-region — 多区域 + 灾备 + 数据驻留 + 容量模型

> 目标态规范「multi-region — 多区域 + 灾备 + 数据驻留 + 容量模型」；写作约束见 [docs/README.md](../README.md)。

## 1. 区域桶模型（DR-001，ADR-031）

> 决策与出口条件见 [ADR-031](../adr/ADR-031-region-residency-sm-crypto-audit-chain.md)；本文只保留可执行设计、量化公式与复制矩阵。

### 1.1 区域桶定义

**区域桶（region bucket）**：以区域为单位的部署与数据承载单元，每个区域桶内含完整数据面（认证执行、会话、数据库、对象存储、审计落盘）；租户归属由 `organizations.region_code` 声明（联动 `deployment_regions` 注册表）。

### 1.2 控制面/数据面拆分

| 面 | 部署范围 | 职责 | 数据 |
|------|---------|------|------|
| **控制面** | 全局（跨区域单逻辑实例，可多副本部署于可信区域） | 租户注册表（套餐/区域归属）、区域路由与发现、平台配置与策略元数据、计量汇聚、管理面全局 API | 仅元数据与注册信息（不含个人身份数据明文） |
| **数据面** | 每区域一套 | 认证/协议面执行、会话与令牌、区域内数据库与对象存储、审计区域落盘 | 全部个人数据与审计数据（不出区域，PRIV-010） |

**租户注册表并发控制**：控制面租户注册表（设计名 `tenant_registrations`；表结构不在本文定义，落地时以 `contracts/schema/*.yaml` 声明为唯一事实源，走 ADR-022 Schema 流程；目标态开放项 OPEN-API-78）带单调递增 `revision`，所有写操作用「读-改-写 + `WHERE revision = $expected`」乐观锁；跨区域迁移期间控制面维护显式「迁移中」状态——迁移完成前新请求仍路由原区域，完成后切换，路由仲裁一律以控制面状态为准。

### 1.3 区域路由

- 登录请求按租户 `region_code` 路由到区域数据面
- 跨区域访问受控并审计（PRIV-010）
- 区域内故障不跨区域扩散（DR-001 验收 4）
- 控制面故障时数据面按既定策略降级运行（已认证会话与协议面继续服务，新租户开通/区域路由变更暂停）
- dedicated 租户实例可指定区域，经 `tenant_instances` 注册表路由

### 1.4 运行期驻留守卫（实现口径）

显式跨租户 target（URL/query/body 的 targetOrganizationId/tenantId/organizationId）由 TenantResolutionMiddlewareWithRegionGuard 在解析出目标组织后比较双方 region_code：

- REGION_RESIDENCY_MODE=observe（默认）：跨 region 或无区域绑定时写结构化 warn（event=region_residency_violation / region_residency_lookup_failed），请求继续，供灰度观测；
- REGION_RESIDENCY_MODE=enforce：跨 region 返回 403 forbidden，无法解析双方区域（如无绑定）同样拒绝（fail-closed）；
- off：关闭比较。守卫基于 organizations.region_code 优先、tenant_instances/deployment_regions 回退的解析实现；同 region 放行、跨 region 拒绝、无绑定拒绝均有真实库用例。

## 2. 复制语义（DR-002）

跨区域复制按数据类别分级，复制矩阵如下（决策与验收口径见 ADR-031 决策 2 与 DR-002）：

| 数据类别 | 区域内一致性 | 跨区域复制 | 依据 |
|---------|------------|-----------|------|
| 平台配置/策略元数据（控制面持有） | 强一致 | 控制面元数据变更经 Outbox 扇出到各区域数据面：按 `event_id` 幂等应用、版本单调递增，回退需显式控制面指令；域事件命名空间 `control.*`（如 `control.tenant_registration.updated`、`control.policy.changed`） | DR-002 |
| 身份主数据 | 区域内强一致 | **不复制**（区域自治，仅控制面持非敏感注册摘要） | PRIV-010 |
| 会话/令牌 | 区域内强一致 | 不复制（跨区域访问重新认证） | DR-002 |
| 审计记录 | 区域内追加写入 + 哈希链 | 异步复制（合规汇聚场景，WORM 归档目标可异地只读） | ADR-031 |
| 计量事件/账期 | 区域内聚合 | 异步汇聚到控制面（喂数边界 METER-005） | — |

## 3. RTO/RPO 分级与演练（DR-002/DR-005）

| 级别 | 场景 | RTO | RPO | 演练节奏 |
|------|------|-----|-----|---------|
| L1 | Pod/单实例故障 | < 1 分钟 | 0 | 每月单实例恢复演练 |
| L2 | 数据库主库故障 | < 5 分钟 | < 5 分钟 | 每季度数据库备份恢复演练 + 密钥版本切换演练 |
| L3 | 数据库损坏 | < 4 小时 | < 15 分钟 | 年度跨场景演练 |

**补充说明**：

- 跨区域场景的 RTO/RPO 单独声明，且不得优于 L1~L3 承诺（DR-002 验收 3）；目标值在区域拓扑与复制链路落地后以演练实测回填，回填前不对外承诺
- 演练须有剧本、实测 RTO/RPO、差距项与整改追踪；记录归档不可篡改（WORM 口径，ADR-031）
- 多区域不影响密钥主权选项；区域级 BYOK/HYOK 配置随租户区域归属生效

## 4. 控制面/数据面拆分触发阈值

**原则**：与《system-overview》物理部署视图一致；拆分按下列量化阈值触发评估。

1. **协议面吞吐阈值**：协议面 QPS 占总 QPS 比例 `ρ_proto` 持续观测窗口高于阈值 `θ_proto` 时，评估把协议面独立部署
2. **单租户容量阈值**：单租户峰值请求 `Q_tenant` 超过 `α × 总容量`，或租户审计日增量 `A_tenant` 超过分区/归档预算时，触发该租户 dedicated 迁移评估
3. **存储驻留阈值**：租户声明驻留区域或合规要求独立数据边界时，直接触发数据面区域拆分
4. **故障域阈值**：区域级故障演练实测 RTO 超出承诺，或跨区域复制延迟持续高于口径时，触发区域扩容/复制拓扑调整

> 阈值 `θ_proto`、`α`、观测窗口与「持续」判据的数值在 L2 压测校准后冻结；冻结前以「公式 + 证据触发」驱动评估。

## 5. 密钥主权与国密适配（DR-003/DR-004）

### 5.1 BYOK/HYOK（DR-003）

与 ADR-009 根密钥外置一致——BYOK 为租户提供密钥材料、平台 KMS 内信封托管（可轮换/吊销）；HYOK 为密钥全程留在租户侧 KMS/HSM、平台仅持引用（加解密经租户授权路径）。吊销密钥后的数据不可读语义与恢复窗口明确；作为套餐可选项。

### 5.2 国密工程适配（DR-004、PRIV-009）

国密以 **crypto 能力位** 落地，不替换国际算法默认值。能力位 ID、缺失策略与 `default`/`gm` 档位的唯一事实源是 `contracts/registries/crypto.yaml`；档位裁决、传输层降级、密码存储与派生、令牌签名、审计链及字段加密边界统一见《[security-model.md](security-model.md)》§2.21 与 ADR-031；启动探测与披露与 ADR-023 多方言能力探测同构。本节不复制能力位清单。

## 6. 容量模型推导

本节给出容量模型的公式与符号定义，供 §4 拆分阈值引用。**示例数值待 L2 校准**，不代表生产承诺。

### 6.1 符号定义

| 符号 | 含义 | 来源/校准方式 |
|------|------|-------------|
| `U` | 租户内用户总数 | 数据集（SRS §11 三档） |
| `MAU` | 月活跃用户 | 计量口径 |
| `r` | 每用户请求率（人均峰值请求/秒） | L2 压测校准 |
| `Q` | 平台峰值 QPS：`Q = Σ U_i × r × σ_i` | L2 校准 |
| `S_u` | 每用户存储占用 | DDL 宽度估算 + L1 实测 |
| `A` | 审计日增量 | `records` 写入速率 |
| `C_1` | 单实例容量（QPS），`C_n = C_1 × n × os` | L2 实测 |
| `os` | 超卖比 = `1/(1+余量)` | 运营策略定 |
| `P` | 单实例连接池 size；`n × P ≤ max_connections × 0.8` | DB 配置 |
| `α` | 单租户容量占比上限 | §4 冻结 |

### 6.2 推导链（五步）

1. **每用户请求率 → 实例数**：`n ≥ ⌈Q / (C_1 × os)⌉`。连接池校验 `n × P ≤ max_connections × 0.8`。
2. **每用户存储占用**：`S_u = S_id + S_cred + (S_sess × 并发会话数) + (A × s_a × 保留天数) / U`，其中 `S_id` 为身份主数据行宽、`s_a` 为单条审计记录均长。存储总占用 ≈ `U × S_u × os_store`（`os_store` 为索引与碎片放大）。
3. **单租户上限**：由 `α × C_n` 反解单租户峰值预算 `Q_i ≤ α × C_n`；α 的取值同时受 bridged schema 数上限与 METER-004 配额模型约束。
4. **超卖比**：`os = 1/(1+余量)` 只作用于**名义容量 → 保证容量**折算；多租户聚合再叠加统计复用（峰值不叠加假设 `ρ_peak < 1`），复用率由 L2 多租户混合压测校准。
5. **规格映射**：Small/Medium/Large 三档 → `(n, P, 存储预算, 限流参数)` 的映射表在 L2 校准后由 [observability.md](observability.md) 的性能基线章节回填。

### 6.3 租户隔离分级套餐

| 套餐 | 数据拓扑 | 连接路由 | 隔离边界 | 目标状态 |
|------|---------|---------|---------|---------|
| shared | 单库单 schema，`organization_id` 行过滤 | 默认连接池；租户上下文 `set_config(..., true)` | 行级 + 数据库 RLS 强制 | 基线形态 |
| bridged | 同库独立 schema（每租户一 schema） | 连接层按租户路由 `search_path` | schema 边界 | 演进形态 |
| dedicated | 独立数据库实例（可指定区域） | 控制面租户注册表路由到独占实例 | 实例边界 | 演进形态 |

- **在线升降级**：受控流水线「导出 → 校验 → 导入 → 双写/比对 → 切换 → 清理」；与 §4 拆分阈值联动
- **性能与定价分层**：三档对应不同限流配额、并发上限、计量速率峰值与备份频率

## 7. 审计链路在多区域场景中的位置

审计哈希链（`records` 表 + 哈希链列 + 锚定快照）在区域内构建；跨区域场景下审计链头锚定可配置为异地只读 WORM 归档目标（DR-002 验收 2、RISK-013/014）。审计链路的写入行为仍为同事务、单区域追加（《data-model》§4.4），复制仅发生在区域内链构建完成后。
