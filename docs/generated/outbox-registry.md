## Worker

- **poll_interval**: 500ms
- **poll_interval_env**: OUTBOX_POLL_INTERVAL_MS
- **poll_interval_desc**: Worker 扫描 status='pending' AND available_at<=now() 的周期
- **batch_size**: `100`
- **batch_size_env**: OUTBOX_BATCH_SIZE
- **batch_size_desc**: 单轮 FOR UPDATE SKIP LOCKED 领取行数
- **lease_seconds**: `30`
- **lease_seconds_env**: OUTBOX_LEASE_SECONDS
- **lease_seconds_desc**: 领取后 locked_by/locked_at 持有期
- **lease_reclaim_seconds**: `60`
- **lease_reclaim_seconds_env**: OUTBOX_LEASE_RECLAIM_SECONDS
- **lease_reclaim_seconds_desc**: locked_at 超过租约时长 ×2 仍未终态的行，由回收扫描重置回 pending
- **max_attempts**: `12`
- **max_attempts_env**: OUTBOX_MAX_ATTEMPTS
- **max_attempts_desc**: 超过进入 dead；全仓统一，DDL 默认 / Worker / AC-WEBHOOK-001 均以此为准
- **backoff_strategy**: 2^n 秒，上限 300s，±20% 抖动
- **backoff_formula**: available_at = now() + min(2^n, 300)s × (1±0.2)
- **backoff_desc**: 抖动防同批事件同时重试；固定，不进环境变量
- **dead_letter_disposal**: 迁入 outbox_dead_letters + records 审计 + 告警；原行保留供追溯
- **dead_letter_desc**: 固定处置，不进环境变量
- **dedup_scope**: (aggregate_type, aggregate_id, event_type)
- **dedup_desc**: 人工重放与消费侧幂等键；同聚合同类型事件只允许一个在途实例
- **dedup_ttl**: 7d
- **dedup_ttl_env**: OUTBOX_DEDUP_TTL_HOURS
- **dedup_ttl_desc**: 去重登记过期物理删除；与 idempotency_keys（24h）不同层不同 TTL

## Webhook

- **signature_header**: GuliangIAM-Signature: t=<unix_sec>,v1=<hex_hmac_sha256(t + '.' + body)>
- **signature_v1_desc**: v1 为对 t + '.' + 原始请求体 的 HMAC-SHA256（密钥为解密后的 webhooks.secret）
- **replay_window**: ±5min
- **replay_window_env**: WEBHOOK_REPLAY_WINDOW_SECONDS
- **replay_window_desc**: 接收侧要求 |now - t| ≤ 300s 且 (t, v1) 首次出现，窗外拒绝
- **status_code_retry_policy**:
  - **no_retry**: 4xx（除 408/429）——语义性失败重试无意义
  - **immediate_dead**: 410 Gone——视为订阅方永久放弃
  - **retry_with_backoff**: 5xx / 429 / 网络超时——按 worker.backoff_strategy 重试
- **ordering**: 按 (aggregate_type, aggregate_id) 分区内串行投递；声明不提供全局顺序
- **outbound_timeout**: 10s
- **outbound_timeout_desc**: 单次投递 HTTP 超时；webhooks.timeout_ms 列可覆盖

## Dedup Layers

| layer | key | ttl | purpose | carrier |
| --- | --- | --- | --- | --- |
| 请求级 | (scope, idempotency_key) | 24h | 防同一客户端重复提交（Idempotency-Key 头） | idempotency_keys 表 |
| 事件级 | (aggregate_type, aggregate_id, event_type) | 7d | 防同一业务事件重复投递（人工重放 + Worker 重试） | outbox 表的 event_id 去重登记 |
| 消费级 | event_id | 由消费者自定 | 消费方幂等 | 消费方自建 |

## Note

TTL 差异是设计选择：请求级覆盖客户端重试窗口（24h）；事件级覆盖人工重放窗口（7d）
